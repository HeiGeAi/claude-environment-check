# 报告格式 1.0.0

每次运行生成独立报告，`checked_at` 为本次开始时间，检查项的 `observed_at` 为相应观察时间。所有时间为 ISO 8601。网页导入显示原始时间和原始范围，不转换为当前电脑的实时检测。

## 顶层

| 字段 | 类型 | 含义 |
| :--- | :--- | :--- |
| schema_version | string | 当前为 1.0.0，不支持的版本拒绝读取 |
| tool_version | string | 生成工具版本 |
| checked_at | string | 本次开始时间 |
| run_location | string | 执行位置声明，local_mac、unknown、ssh、container、cloud 或 browser |
| scope | object | 本地、联网、doctor、路径与目标端点等范围 |
| platform | object | 安全的平台摘要 |
| overall | string | INCOMPLETE、ISSUES_FOUND 或 VERIFIED_IN_SCOPE |
| checks | array | 至多 150 项检查记录 |
| limitations | array | 覆盖缺口与解释边界 |

## 单项

检查项含 `id`、`status`、`required`、`observed_at`、`source`、`evidence_level`、`observed`、`message`、`remediation`。ID 唯一。`observed` 为大小和深度受限的安全结构，不能装入原始配置或命令日志。

| 状态 | 含义 |
| :--- | :--- |
| PASS | 当前所述项目在所述范围得到验证 |
| FAIL | 有证据的已定义问题 |
| WARN | 需关注的配置或运行线索 |
| UNKNOWN | 权限不足、采集失败、格式未支持或证据不足 |
| SKIPPED | 本次未选择、未执行或不适用，说明中附原因 |

证据级别：`configuration`、`runtime`、`normal_probe`、`isolated_path_test`、`system_fault_drill`。不能由静态配置推导故障演练通过。

整体聚合顺序：有 FAIL 为 ISSUES_FOUND；必检项有非 PASS 为 INCOMPLETE；存在 WARN 为 ISSUES_FOUND；否则必检范围通过为 VERIFIED_IN_SCOPE。网页导入重新聚合，不相信文件声明的 overall。没有必检项的空报告保持 INCOMPLETE。

Python 退出码依次为 0（当前必检范围通过）、1（发现问题）、2（运行失败）、3（必检范围不足）。权限未知和选项未执行仍保留在报告里，退出码不能描述整机安全。

## 地址表达

同一次运行的相同地址使用相同随机别名；IPv4 与 IPv6 分组比较。不同报告的别名不能直接比较，也不承诺跨报告稳定。导出无原始地址与可枚举哈希。

探针失败、跨域阻止、候选缺失与未做断线演练都不能转换为未泄漏或安全通过。

## 导入限制

JSON 至多 1 MiB，数组长度、字段长度和嵌套深度有限制。报告内容作为文本展示，无 HTML 执行、远程资源加载或报告内命令执行。导入和重新导出仍不代替本人对敏感信息的复查。
